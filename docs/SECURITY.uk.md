# Нотатки з безпеки

[Англійська версія](SECURITY.md)

OneAIWorkers дає AI-помічнику змогу читати публічні сторінки й викликати зовнішні сервіси. Ставтесь до цього як до справжньої автоматизації.

## Безпечні початкові налаштування

- Він не виконує довільний код від AI.
- Workers плагінів можуть використовувати тільки перевірені пакунки або готові шаблони.
- Інструменти для публічних посилань блокують локальні й приватні адреси.
- Плагіни, створені вручну, використовують назви секретів Cloudflare.
- Ключі плагінів із каталогу шифруються через AES-GCM перед записом у D1.
- Результати інструментів приховують чутливі поля в URL: `token`, `key`, `secret`, `password`, `auth`, `signature`.
- D1 використовується для OAuth, реєстру плагінів, зашифрованих ключів, дій, пошуку, великих результатів і записів аудиту. Вона не використовується для памʼяті ШІ.

## Ключі плагінів із каталогу

Встановлювач створює `CREDENTIALS_MASTER_KEY` як секрет Cloudflare. Його значення не записується в Git, каталог або пакунок плагіна.

Користувач вводить ключ сервісу лише на короткочасній сторінці власного OneAIWorkers. Worker шифрує значення через AES-GCM із прив’язкою до конкретного плагіна, а потім записує його в D1. Каталог і центральний встановлювач цього ключа не отримують.

Пакунок плагіна перевіряється за контрольною сумою з каталогу. Основний Worker приймає Worker плагіна лише тоді, коли підтвердження має правильний підпис ECDSA, призначене саме для його адреси, ще діє і не використовувалося раніше.

## Доступ до MCP

Звичайний встановлювач створює `MCP_SHARED_SECRET` автоматично. Якщо ви встановлюєте OneAIWorkers вручну, створіть цей секрет самі перед підключенням MCP-клієнта.

Самої адреси Worker недостатньо для доступу до `/mcp`. Нове OAuth-підключення має пройти перевірку спільного секрету. Публічні службові сторінки можуть показувати відомості про версію або оновлення, але не показують дані плагінів чи значення секретів.

Worker приймає його одним із цих способів:

- `Authorization: Bearer <secret>`;
- `x-oneaiworkers-token: <secret>`;

Секрети й токени доступу OAuth навмисно не приймаються в параметрах URL, бо посилання можуть потрапляти в журнали або історію браузера.

Для навмисно публічного застосунку треба окремо продумати правила доступу, а не просто вимикати захист.

OAuth вимагає PKCE з `S256`. Токен доступу діє одну годину. Клієнт може запросити `offline_access`, щоб отримати одноразовий токен поновлення. Токени OAuth можна відкликати через `/oauth/revoke`.

## Доступ до Cloudflare

Встановлювач у браузері отримує тимчасовий дозвіл Cloudflare для створення або оновлення Workers. Після завершення він відкликає дозвіл.

Встановлений OneAIWorkers не зберігає цей дозвіл. Для встановлення плагіна з каталогу не потрібен постійний `CF_API_TOKEN`.

## Попередження про Worker плагіна

Кожен Worker плагіна з каталогу має власний випадковий ключ доступу. Основний Worker зберігає його зашифрованим і викликає плагін через HTTPS. Самої адреси Worker плагіна недостатньо для доступу до його дій.

## Повідомлення і webhook

Інструменти для повідомлень можуть надсилати реальні повідомлення й викликати реальні сервіси.

Рекомендований порядок:

1. Прочитати або перевірити дані.
2. Дати AI-помічнику вирішити, чи це важливо.
3. Надсилати повідомлення або викликати webhook тільки коли правило чітке.
4. Дати AI-помічнику запамʼятати, що сталося.

## Не використовуйте в першій версії для

- оплат або повернень коштів;
- видалення робочих даних;
- автоматичного надсилання листів клієнтам;
- публікації в соцмережах без перевірки людиною;
- виконання довільного коду, створеного AI.
