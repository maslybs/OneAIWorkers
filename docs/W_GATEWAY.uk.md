# W Gateway і пакунки плагінів

## Сталий набір MCP-команд

Основна адреса `/mcp` працює в режимі `meta` і показує лише:

```text
w_search
w_describe
w_call
w_present
w_result_read
w_agent_run
```

Список не змінюється після встановлення, оновлення, вимкнення або видалення плагіна. Старі адреси `/mcp/direct` і `/mcp/hybrid` вимкнені. Для контрольованого переходу їх можна тимчасово ввімкнути через `W_ENABLE_LEGACY_DIRECT=true`.

Кожна відповідь цих шести команд перевіряє оновлення OneAIWorkers. Якщо доступна новіша версія, відповідь починається з повідомлення та прямого посилання «Оновитися». Короткий кеш не дозволяє повторно завантажувати файл версії для кожної команди.

Команди керування реєстром відокремлені на `/mcp/admin` і потребують прав адміністратора.

## Як працює пошук

До пошуку `w_search` перевіряє права адреси, власника, користувача, цільову платформу, наявність підключення, дозволи на читання або запис і стан плагіна.

Для невеликого каталогу пошук працює без Workers AI:

1. точні назви та посилання;
2. текстовий пошук D1 FTS5;
3. доступність і частку успішних виконань.

Векторний пошук додається лише тоді, коли одночасно виконано дві умови:

- користувачу доступно щонайменше 20 плагінів;
- точний і текстовий пошук не дали впевненої відповіді.

Точна назва або точне посилання не запускають Workers AI навіть у великому каталозі. Поріг можна змінити через `W_SEMANTIC_PLUGIN_THRESHOLD`. Значення за замовчуванням — `20`.

`w_search` повертає `search_mode: "text"` для простого пошуку і `search_mode: "hybrid"`, якщо справді використано вектори.

Відповідь містить лише стислий опис. Повних схем і векторів у ній немає. `w_describe` читає збережені схеми для щонайбільше десяти вибраних незмінних посилань.

Реєстр не перебудовується перед кожним пошуком. OneAIWorkers позначає його застарілим після встановлення, оновлення, вимкнення або видалення плагіна, зміни налаштувань доступу чи оновлення самого OneAIWorkers. Тільки тоді виконується синхронізація.

## Виконання дії

`w_call` приймає лише встановлене незмінне посилання:

```text
<plugin_id>:<capability_id>/<method>@<version>
```

Перед виконанням він перевіряє схему, права, підключений обліковий запис, потрібні дозволи сервісу, одноразове підтвердження і ключ захисту від повтору. Усі дії проходять через один виконавець. Довільну адресу або метод запиту передати не можна.

Результат довший за 24 000 символів зберігається у D1 або R2. Клієнт отримує стислий перегляд і `result_id`. `w_result_read` читає лише дозволену частину для того самого власника, користувача, адреси й сеансу.

## Ключі плагінів

Єдиним джерелом даних для ключів плагінів є зашифровані записи у D1. Захищена сторінка налаштувань працює і для плагінів із каталогу, і для плагінів, доданих вручну.

Якщо старий внутрішній плагін ще використовує ключ Cloudflare, наприклад `N8N_PSY_API_KEY`, OneAIWorkers під час синхронізації переносить його значення у зашифроване сховище D1. Після цього дії читають ключ із D1, а W Gateway бачить плагін як підключений. Збереження нового значення позначає реєстр застарілим, тому наступний `w_call` або `w_search` автоматично оновлює стан підключення.

`delete_plugins` видаляє кілька вибраних плагінів та їхні налаштування після одного підтвердження користувача. Після підтвердження у браузері MCP-клієнт має повторити той самий `w_call` з незмінними параметрами та отриманим ключем підтвердження. Звичайна перевірка списку плагінів не виконує видалення.

## `oneai.plugin.v1`

Мінімальний опис пакунка:

```json
{
  "format": "oneai.plugin.v1",
  "id": "example",
  "name": "Example",
  "version": "1.0.0",
  "description": "Приклад хмарного плагіна.",
  "targets": ["oneaiworkers-cloudflare"],
  "capabilities": [
    {
      "kind": "plugin",
      "id": "api",
      "target": "oneaiworkers-cloudflare",
      "artifact": "cloud/plugin.json"
    }
  ],
  "permissions": {
    "network": ["configured-service-host"],
    "secrets": ["service_api_key"]
  }
}
```

Опублікована версія незмінна. Зміна схеми або поведінки потребує нової версії. Відкат лише вибирає попередню опубліковану версію і не переписує її.

## Виконувані навички

Звичайний `SKILL.md` лишається інструкцією. Для виклику потрібен опис `oneai.skill-api.v1`:

```json
{
  "format": "oneai.skill-api.v1",
  "runtime": "javascript",
  "entry": "scripts/runner.js",
  "methods": [
    {
      "name": "request_plan",
      "description": "Створити визначений план.",
      "dispatch": { "input.mode": "request_plan" },
      "input_schema": {
        "type": "object",
        "properties": { "task": { "type": "string" } },
        "required": ["task"],
        "additionalProperties": false
      },
      "output_schema": { "type": "object" },
      "annotations": {
        "read_only": true,
        "destructive": false,
        "requires_confirmation": false
      }
    }
  ]
}
```

Хмарна публікація відхиляє виконувану навичку без підтримуваного середовища, явної точки входу, повних схем методів, прав і опису побічних дій.

## Реєстр D1

Нормалізований реєстр використовує таблиці з префіксом `w_` для плагінів, версій, можливостей, дій, назв, прикладів, векторів, груп, завдань, облікових записів, прав, підтверджень, захисту від повтору, великих результатів і журналів.

D1 є джерелом правди. Пізніше можна додати прискорювач пошуку, але його треба повністю відновлювати з D1. Він не замінює запис про публікацію у D1.
