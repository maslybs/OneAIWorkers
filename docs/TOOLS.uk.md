# MCP-інструменти

[Англійська версія](TOOLS.md)

OneAIWorkers дає AI-помічнику невеликий набір інструментів.

AI-помічник памʼятає, порівнює й вирішує. Worker тільки виконує дію.

## `hub_info`

Показує, що вміє OneAIWorkers і які додаткові сервіси налаштовані.

## Конектори з каталогу

### `connector_installation_help`

Використовується, коли користувач питає, як встановити конектор, але ще не назвав сервіс або потрібну дію. Пояснює справжній порядок і забороняє вигадувати розділ Marketplace на головній сторінці Worker чи неперевірені конектори.

### `find_capability`

Шукає хмарний конектор для названого сервісу або задачі користувача. OneAIWorkers завантажує публічний каталог і порівнює варіанти всередині власного Worker. Текст задачі не надсилається до каталогу. Знайдений варіант містить точне посилання для встановлення у браузері. Лише повернуті результати можна називати доступними.

### `list_connector_updates`

Перевіряє встановлені конектори з каталогу. Якщо є нова версія, повертає посилання для оновлення у браузері.

### `get_connector_settings_link`

Створює короткочасне одноразове посилання для додавання або зміни ключів конектора. Не просіть користувача надсилати ключ у чаті.

### `list_connectors` і `call_connector_tool`

Це дві постійні живі дії. Під час кожного виклику вони читають поточний реєстр із D1.

- `connector_id: system` — встановлення, налаштування, оновлення, збереження, перевірка та видалення.
- `connector_id: native` — поточні дії Workers AI та агентів.
- Збережені конектори використовують власний `connector_id`.

Для старих клієнтів відомі системні дії також працюють через `native`. Оновлення списку команд необов’язкове й лише додає короткі окремі команди.

### `save_connector`

Спосіб для розробників і прямих HTTP API. Налаштування зберігаються в D1, а ключі беруться із секретів Cloudflare за назвою. Готові пакунки з каталогу не потребують цього ручного кроку.

## Читання і перевірка

### `fetch_url`

Читає одну публічну HTTPS-сторінку і повертає текст.

Використовуйте для того, щоб:

- стежити за змінами на сторінці;
- перевіряти ціни конкурентів;
- читати публічну документацію;
- перевіряти публічну JSON або текстову адресу.

### `fetch_many_urls`

Читає до 10 публічних HTTPS-сторінок за один виклик.

Використовуйте для кількох сторінок або конкурентів.

### `fetch_rss`

Читає RSS або Atom-стрічку і повертає останні записи.

Використовуйте для новин, блогів, списків змін або досліджень.

### `check_url_status`

Перевіряє, чи працює публічне посилання і скільки часу займає відповідь.

Використовуйте для перевірки сайту або API.

## Дії

### `send_notification`

Надсилає повідомлення в Telegram, Discord, Slack або webhook.

### `call_webhook`

Викликає HTTPS webhook з JSON-даними.

Використовуйте для запуску Make, Zapier, n8n або вашої системи.

## Створення Worker

### `create_child_worker_from_template`

Створює дочірній Cloudflare Worker із безпечного шаблону.

Поточний шаблон:

- `webhook-forwarder`: пересилає POST, PUT і PATCH запити до налаштованої HTTPS-адреси.

Це старіший спосіб для розробників. Дочірні Workers із каталогу встановлюються через браузер і не потребують постійного ключа Cloudflare API.

## Типовий порядок роботи

```text
Запуск AI за розкладом
  -> прочитати або перевірити дані через OneAIWorkers
  -> порівняти з памʼяттю AI
  -> вирішити, що важливо
  -> надіслати повідомлення або викликати webhook
  -> запамʼятати результат
```
